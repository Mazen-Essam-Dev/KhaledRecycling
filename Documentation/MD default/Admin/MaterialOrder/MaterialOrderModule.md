## Material Order Module

This document describes the **Material Order** feature, including the MVC controller, application service, and the domain entities involved.

---

## Overview

The Material Order module allows trainers and managers to:

- Create and edit material orders.
- Filter and view lists of material orders.
- Print reports and export Excel files.
- Approve orders using OTP (SMS-based) signatures from trainers and managers.

Key components:

- `MaterialOrderController` (MVC Controller – Admin Area)
- `MaterialOrderService` (Application Service)
- `MaterialOrder` and `MaterialOrderItem` (Domain Entities)

---

## Domain Entities

### `MaterialOrder`

Represents the header of a material order.

- **Id** (`int`, Key)
- **MaterialOrderCode** (`string`, required, max length 50)  
  Sequential code generated by the service (`GetNewCodeAsync`).
- **DepartmentId** (`int?`, required)  
  Foreign key to `Department`.
- **Department** (`Department?`)  
  Navigation property.
- **UserId** (`string?`, required)  
  The user who created the order.
- **TrainerId** (`int?`)  
  Optional link to trainer.
- **Date** (`DateOnly?`, required, `date` column)  
  Order date.
- **OrderTotal** (`decimal?`, default `0.00m`)  
  Sum of (Quantity × SinglePrice) of all items; maintained in the service.
- **Items** (`ICollection<MaterialOrderItem>`)  
  Collection of order line items.
- **Notes** (`string?`, max length 500)
- **SignatureUserId** (`int?`)  
  FK to `Signature` (trainer signature).
- **SignatureUser** (`Signature?`)  
  Trainer signature navigation.
- **SignatureManagerId** (`int?`)  
  FK to `Signature` (manager signature).
- **SignatureManager** (`Signature?`)  
  Manager signature navigation.

---

### `MaterialOrderItem`

Represents a single line item in a material order.

- **MaterialOrderItemId** (`int`, Key)
- **MaterialOrderId** (`int`, required)  
  FK to `MaterialOrder`.
- **MaterialOrder** (`MaterialOrder?`)  
  Navigation property.
- **Quantity** (`int?`, default `0`)  
- **SinglePrice** (`decimal?`, default `0.00m`)  
  With range validation to ensure positive numeric value.
- **ItemName** (`string?`, max length 200)  

`OrderTotal` of the header is calculated as the sum of `Quantity × SinglePrice` of all items.

## Application Service: `MaterialOrderService`

Namespace: `Application.Services.Admin`

Implements `IMaterialOrderService`. Handles all business logic and data access related to material orders.

### Dependencies (Constructor Injection)

- `IUnitOfWork _unitOfWork`  
  Generic repository / UoW abstraction for DB operations.
- `IWebHostEnvironment _env`
- `IHttpContextAccessor _httpContextAccessor`
- `ISMSService _SMSService`
- `ISMSForSendingOTPService _SMSForSendingOTPService`

### Methods

#### `Task<IEnumerable<MaterialOrder>> GetAllAsync()`

Returns all material orders including:

- `SignatureUser`
- `SignatureManager`
- `Department`

Used for listing and reporting.

#### `Task<IEnumerable<Supplier>> GetAllSuppliersAsync()`

Returns a lightweight list of suppliers:

- `Id`
- `SupplierNameAr`
- `SupplierNameEn`

#### `Task<string> GetNewCodeAsync()`

Generates the next `MaterialOrderCode`:

1. Gets the last `Id` in `MaterialOrders`.
2. Retrieves the corresponding `MaterialOrderCode`.
3. Attempts to parse it as an integer.
4. Increments and formats to 4 digits (`D4`), e.g. `0001`, `0002`, etc.

#### `Task<MaterialOrder?> GetByIdAsync(int id)`

Returns a material order by `Id` with:

- `Items`
- `SignatureUser`
- `SignatureManager`
- `Department`

#### `Task<IEnumerable<int>> GetAllYearsInDb()`

Returns distinct years that appear in `MaterialOrder.Date`, sorted ascending.

#### `Task<int> AddAsync(MaterialOrder entity)`

Adds a new material order:

1. Iterates through `entity.Items`:
   - Ensures `SinglePrice` and `Quantity` are non-null.
   - Calculates row total and adds to `totalAll`.
   - Sets `MaterialOrderId`.
2. Sets `entity.OrderTotal = totalAll`.
3. Ensures `MaterialOrderCode` is unique; if duplicate, regenerates via `GetNewCodeAsync`.
4. Adds entity and commits.
5. Returns the new `Id`.

#### `Task UpdateAsync(MaterialOrder entity)`

Updates an existing material order:

1. Loads existing entity from DB.
2. Deletes existing `MaterialOrderItem` records for this order.
3. Re-adds items from `entity.Items`, recalculating `OrderTotal`.
4. Preserves `UserId` from the existing record.
5. Uses `_unitOfWork.MaterialOrders.UpdateValues` to update scalar properties.
6. Saves changes.

#### `Task DeleteAsync(int id)`

Deletes a material order and its items:

- Loads entity.
- Removes all related `MaterialOrderItems`.
- Deletes `MaterialOrder`.
- Saves changes.

#### `Task<bool> CheckIsMonthRegistedBefore(int id, DateOnly? dateOnly)`

Checks whether another record (different `Id`) exists with the same year and month as `dateOnly`. Used to enforce one record per month logic (if needed). Returns:

- `true` if there is **any existing record** for that month (other than current id).
- `false` otherwise.

#### `Task<bool> SendOtpAsync()`

1. Uses `OTPHelper.SaveOtpAsync` to generate and store an OTP for the current user.
2. Sends the OTP via `_SMSForSendingOTPService.SendOtpSMSAsync`.
3. Returns `true` if SMS sending succeeds.

#### `Task<(bool success, string? message)> ValidateOtpAsync(int id, string code, string role)`

Validates OTP and applies digital signature:

1. Validates OTP using `OTPHelper.ValidateOtpAsync`.
2. Loads the `MaterialOrder` by `id`.
3. Gets current user id from `HttpContext` (extension `GetUserId()`).
4. Loads all signatures, picks the **latest** signature for this user (`CreatedAt` DESC).
5. If no signature found → returns error.
6. If `role == "Trainer"`:
   - Sets `materialOrder.SignatureUserId` to latest signature id.
7. If `role == "Manager"`:
   - Requires that trainer signature exists first.
   - Sets `materialOrder.SignatureManagerId`.
8. Saves changes and returns `(true, null)` on success.

### Helper: `CheckLoggedUserIfTrainerAndReturnData()`

Attributes: `[IgnoreAction]`, `[NoLogging]`  
Returns `Task<(string userId, int trainerId, int departmentId)>`.

Logic:

1. Gets logged-in username (email) from `HttpContext.User.Identity.Name`.
2. Loads `ApplicationUser` from `_unitOfWork.Users`.
3. Loads corresponding trainer by `UserId`.
4. If trainer exists, returns:
   - `UserId`
   - `TrainerId`
   - `DepartmentId`
5. If no trainer, returns user id and `0` for trainer and department.

This is used to restrict data to the logged-in trainer and pre-fill forms.
