    Material Order Module – Full Documentation

    Material Order Module – Overview

    Purpose Manage material orders for trainers and managers with filtering, printing, Excel export, and OTP-based approval.
    Main Components MaterialOrderController – MVC Controller (Admin Area)
    MaterialOrderService – Application Service
    MaterialOrder & MaterialOrderItem – Domain Entities
    Key Features Create and edit material orders
    Filter and view lists by user, department, and date range
    Print list and single orders
    Export filtered list to Excel (AR/EN)
    OTP-based Trainer / Manager signatures

    MaterialOrder Entity

    IdPrimary Key (int)
    MaterialOrderCode Required string, max length 50
    Sequential code generated by service (GetNewCodeAsync)
    DepartmentId Required int?
    Foreign key to Department
    Department Navigation property to Department
    UserId Required string?
    Application user who created the order
    TrainerId Optional trainer reference (int?) for logged trainer scenario
    Date Required DateOnly?
    Stored as date column (order date)
    OrderTotal Decimal? (default 0.00)
    Sum of (Quantity × SinglePrice) for all items
    Calculated and maintained in service
    Items ICollection<MaterialOrderItem>
    Collection of order line items
    Notes Optional notes (string?, max length 500)
    SignatureUserId int?
    Foreign key to Signature for Trainer signature
    SignatureUser Navigation property to trainer Signature
    SignatureManagerId int?
    Foreign key to Signature for Manager signature
    SignatureManager Navigation property to manager Signature

    MaterialOrderItem Entity

    MaterialOrderItemIdPrimary Key (int)
    MaterialOrderId Required int
    Foreign key to MaterialOrder
    MaterialOrder Navigation property to MaterialOrder
    Quantity int?, default 0
    Optional, validated as numeric
    SinglePrice decimal?, default 0.00
    Range validation to ensure positive numeric value
    ItemName string?, max length 200
    Description of the requested material

    MaterialOrderService – Core Methods

    GetAllAsync Returns all material orders including:
    SignatureUser, SignatureManager, Department
    Used for listing, print, and export
    GetAllSuppliersAsync Returns lightweight supplier list:
    Id, Arabic name, English name
    GetNewCodeAsync Generates next sequential MaterialOrderCode
    Reads last Id and code, parses numeric part, increments, formats as 4 digits (D4)
    GetByIdAsync Retrieves single order by Id with:
    Items, SignatureUser, SignatureManager, Department
    GetAllYearsInDb Returns distinct years from MaterialOrder.Date
    Used for year-based filtering or reports
    AddAsync Adds new MaterialOrder
    Iterates items, ensures Quantity/SinglePrice non-null
    Calculates row totals and OrderTotal
    Ensures unique code; generates new if collision
    Saves and returns new Id
    UpdateAsync Updates existing order
    Loads current record, deletes existing items
    Adds new items and recalculates OrderTotal
    Preserves UserId and updates scalar fields via UpdateValues
    Saves changes
    DeleteAsync Deletes order and its items
    Removes related MaterialOrderItem records, then header
    CheckIsMonthRegistedBefore Checks if another record exists in same year/month (excluding current Id)
    Used to prevent duplicate monthly records when required
    SendOtpAsync Generates OTP via OTPHelper.SaveOtpAsync
    Sends OTP using ISMSForSendingOTPService
    Returns true on SMS success
    ValidateOtpAsync Validates OTP using OTPHelper.ValidateOtpAsync
    Loads MaterialOrder by Id
    Fetches latest signature for current user
    If role = Trainer → sets SignatureUserId
    If role = Manager → requires trainer signature first, then sets SignatureManagerId
    Saves and returns success / message

    Helper – CheckLoggedUserIfTrainerAndReturnData

    Attributes [IgnoreAction]
    [NoLogging]
    Return Type Task<(string userId, int trainerId, int departmentId)>
    Logic Reads logged-in username (email) from HttpContext.User
    Loads ApplicationUser and associated Trainer
    If trainer exists → returns user id, trainer id, department id
    Else → returns user id and zeros for trainer/department
    Used to filter data and pre-fill forms for trainers

    Controller Actions – Main

    Index Attributes: [YesGet]
    Lists material orders with filters:
    User, Department, DateFrom, DateTo
    Trainer user sees only own orders
    Uses PaginatedList<MaterialOrderVM> (page size 50)
    Ajax support: returns _ListPartial when requested via XMLHttpRequest
    AddEdit (GET) Creates or edits material order
    Generates new code via service for new orders
    If trainer logged, pre-fills trainer, user, department and flags IsTrainerLogged
    Loads department and user dropdowns
    AddEdit (POST) Attributes: [HttpPost], [ValidateAntiForgeryToken]
    Reapplies trainer context (if any)
    On validation failure: rebind dropdowns and keep code
    On success: maps to MaterialOrder and calls AddAsync or UpdateAsync
    Redirects to Index (create) or back to AddEdit (edit)
    Delete Attributes: [HttpPost]
    Deletes order via service and redirects to Index

    Controller Actions – Details & Reporting

    Details Attributes: [IgnoreAction], [YesGet]
    Read-only view of single order
    Loads applicant name from ApplicationUser
    Loads TrainerSignedName and ManagerUserName from signature users
    Print Attributes: [IgnoreAction], [YesGet]
    Printer-friendly list of orders
    Same filters as Index, no pagination
    Uses MaterialOrderVM list
    PrintDetails Attributes: [IgnoreAction], [YesGet]
    Printable single order
    Can include suppliers data for display
    createExcelReport_Download Attributes: [IgnoreAction], [YesGet]
    Filters like Index
    Builds ExcelDataDTO list with Code, Date, Department, Applicant
    Supports AR / EN via Resource1 and Session language
    Calls ExcelStaticReport.ExcelReportArEn_ and returns XLSX file

    OTP & SMS Approval Workflow

    SendOtp Attributes: [IgnoreAction], [NoLogging], [HttpPost]
    Calls service SendOtpAsync
    Returns JSON: { success = true/false }
    ValidateOtp Attributes: [HttpPost], [IgnoreAction]
    Accepts OtpValidationRequest (Id, Code, Role)
    Validates OTP via service
    If Role = Trainer and success → sends SignalR and notification to Manager role about new request ready for approval
    Returns JSON with success and message
    Trainer Role Signs as applicant (SignatureUserId)
    Triggers notifications to managers
    Manager Role Signs as manager (SignatureManagerId)
    Requires Trainer signature to exist first
